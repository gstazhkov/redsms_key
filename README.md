# RedSMS KB — сохранение в базу данных на сервере + Wiki

Теперь изменения (добавление/удаление карточек, смена статуса, импорт)
сохраняются не только в `localStorage` браузера, а в настоящей базе
данных SQLite на сервере. Это значит:

- данные видны всем, кто открывает базу знаний, а не только в одном браузере;
- при очистке кэша браузера или переходе с другого устройства данные не теряются;
- сохраняется история последних 50 версий на случай, если что-то нужно откатить.

Также в приложение добавлена вторая вкладка — **📝 Wiki**: свободная база
знаний в стиле Notion со страницами, вложенными подстраницами и простым
текстовым редактором (заголовки, списки, цитаты, код, ссылки). Данные Wiki
хранятся на том же сервере, в отдельной таблице SQLite, точно так же, как
и основная база знаний — с автосохранением, офлайн-кэшем в `localStorage`
и историей последних 50 версий.

## Что внутри

```
redsms-kb/
├── server.js             — сервер (Express + SQLite)
├── package.json
├── seed-data.json        — исходные данные базы знаний (68 карточек),
│                           которыми база заполняется при самом первом запуске
├── wiki-seed-data.json   — исходные данные Wiki (приветственная страница
│                           с примером подстраницы), которыми Wiki заполняется
│                           при самом первом запуске
├── public/
│   └── index.html        — сама страница (вкладки «База знаний» и «Wiki»)
└── data/                 — здесь появится файл базы данных kb.db (создаётся сам,
                             хранит и базу знаний, и Wiki)
```

## Установка и запуск

Понадобится **Node.js версии 22.5 или новее** (рекомендуется 24+).
Сервер использует встроенный в сам Node.js модуль `node:sqlite` — никаких
нативных модулей и компиляторов (Visual Studio / build tools) устанавливать
не нужно, `npm install` ставит только `express`.

Проверить свою версию Node:
```bash
node --version
```
Если версия ниже 22.5 — обновите Node.js (например, с https://nodejs.org,
рекомендуется LTS-версия 24.x или новее).

```bash
cd redsms-kb
npm install
npm start
```

При запуске на Node 22.x в консоли появится предупреждение вида
`ExperimentalWarning: SQLite is an experimental feature` — это ожидаемо
и не мешает работе. На Node 24+ этого предупреждения не будет.

После запуска сервер поднимется на `http://localhost:3000` — там же
будет доступна и сама страница (`public/index.html` отдаётся автоматически),
и API. Открывать файл `index.html` напрямую (двойным кликом) больше
не нужно и не будет работать с сохранением — страницу нужно открывать
именно через адрес сервера.

Порт можно поменять переменной окружения `PORT`:

```bash
PORT=8080 npm start
```

## Ключ доступа к API (важно)

Чтобы сохранять данные, фронтенд отправляет заголовок `X-API-Key`.
По умолчанию используется значение `redsms` (совпадает с паролем входа
в само приложение). Чтобы задать свой секретный ключ:

1. На сервере: `API_KEY=ваш_секрет npm start` (или через переменные окружения
   вашего хостинга).
2. В файле `public/index.html` найдите строку:
   ```js
   const API_KEY = 'redsms';
   ```
   и замените на тот же ключ, что задали на сервере.

Без совпадения ключей чтение данных (GET) будет работать всегда, а вот
сохранение (PUT) — нет, сервер ответит `401 Unauthorized`.

⚠️ Учтите: пароль входа в само приложение (`redsms`) и API-ключ хранятся
в открытом виде в JS на клиенте — это подходит для внутреннего
инструмента команды поддержки, но не является защитой уровня
production для чувствительных данных. Если нужен более серьёзный
уровень безопасности — стоит добавить полноценную авторизацию
(например, через отдельный логин/сессию) на уровне сервера.

## Как это работает

- При открытии страницы фронтенд делает `GET /api/kb` и получает
  актуальные данные с сервера. Если сервер недоступен — используются
  данные, ранее сохранённые в `localStorage` браузера (офлайн-резерв).
- При любом изменении (новая карточка, смена статуса, удаление,
  импорт JSON) фронтенд делает `PUT /api/kb`, отправляя весь набор
  данных целиком, и сервер сохраняет их в SQLite.
- Кнопка «🔄 Обновить с сервера» в сайдбаре позволяет вручную
  подтянуть свежие данные — полезно, если базу правит ещё кто-то
  параллельно.
- Кнопки «Экспорт» / «Импорт» работают как раньше — это способ
  сделать резервную копию в файл или загрузить данные из файла.

### Вкладка Wiki

Работает по тем же принципам, но независимо от базы знаний, через
отдельный эндпоинт `/api/wiki`:

- страницы хранятся в дереве (у каждой есть `parentId` — родительская
  страница или `null` для страниц верхнего уровня);
- заголовок и текст страницы сохраняются на сервере автоматически,
  с небольшой задержкой после того, как вы прекратили печатать
  (индикатор «✓ Сохранено на сервере» под заголовком страницы);
- кнопки ➕ / 🗑️ у каждой страницы в дереве (появляются при наведении)
  добавляют подстраницу или удаляют страницу вместе со всеми вложенными;
- в сайдбаре Wiki есть свои кнопки «🔄 Обновить с сервера», «📥 Экспорт»
  и «📤 Импорт» — работают так же, как у базы знаний, но с файлом вида
  `wiki-export-*.json`.

## Деплой на реальный сервер / хостинг

Вариантов много, самый простой — VPS с Node.js:

1. Скопируйте папку `redsms-kb` на сервер.
2. `npm install --production`
3. Запустите через процесс-менеджер, чтобы сервер не падал и
   поднимался заново при перезагрузке, например через `pm2`:
   ```bash
   npm install -g pm2
   pm2 start server.js --name redsms-kb
   pm2 save
   pm2 startup
   ```
4. Настройте реверс-прокси (Nginx) на порт сервера (по умолчанию 3000)
   и, желательно, HTTPS.

Резервное копирование: файл базы данных лежит в `data/kb.db` — его
достаточно периодически копировать (например, `cp data/kb.db backup/`)
или включить в общий бэкап сервера.
