PushOK (SIM-Push) **Вопрос про безопасность — развёрнутый ответ:** ### Как работает PushOk Технически это работает как исходящий звонок, инициируемый через API REDSMS. Клиент не принимает звонок и не слушает сообщение, а сбрасывает вызов. REDSMS сверяет номер звонящего (Caller ID) с номером, переданным в запросе, и возвращает результат верификации. Клиент инициирует запрос к API REDSMS с параметром `route=pushok`, указывая номер телефона и текст сообщения. Затем REDSMS совершает звонок на этот номер, и если он был успешно принят (или сброшен), подтверждается, что номер активен и принадлежит пользователю. ### Уровни безопасности PushOk **1. Инфраструктурная безопасность REDSMS:** - **Аутентификация по API** — каждый запрос требует логина, временной метки (`ts`) и секретного ключа (`secret`), формируемого как MD5-хеш от временной метки и API-ключа. - **Белый список IP-адресов** — в личном кабинете можно настроить список разрешённых IP; запросы с других адресов отклоняются с ошибкой `401 Unauthorized`. - **Защита от злоупотреблений:** - Лимит на дубликаты — временной интервал, в течение которого сообщения на один номер считаются дубликатами и блокируются. - Общие лимиты — ограничения на количество сообщений в сутки, на уникальный номер и на уникальный номер с одинаковым текстом. - Баланс и лимиты расходов — запрос может быть отклонён при недостатке средств или превышении месячного лимита расходов. **2. Логическая безопасность на стороне клиента:** - **Сопоставление с транзакцией** — необходима надёжная связка `uuid` сессии верификации с конкретной транзакцией (заказом, списанием баллов). - **Обработка несовпадения номеров** — клиентская логика должна чётко определять действия при несовпадении номера звонящего с переданным в запросе (отказ в операции, запрос альтернативного способа верификации и т.д.). ### Резюме PushOk — верификационный сервис с API-управлением, безопасность которого обеспечивается на уровне API (аутентификация, IP-фильтры, лимиты) и на уровне бизнес-логики клиента (сопоставление сессии с транзакцией, обработка результата). Подходит для сценариев двухфакторной аутентификации как альтернатива SMS без необходимости вводить код с экрана. **Ответ:** *(шаблон для быстрого ответа отсутствует, используется развёрнутый текст выше)* --- ## 15. После этого система инициирует отправку SMS. > > Такой подход позволит существенно повысить процент доставки кодов, сохранив при этом экономию на SMS. > > Ознакомиться с процессом подключения и настройки можно по ссылке: https://docs.redsms.ru/http/send-message-fcall/ **Иные проблемы и уточнения:** Трафик может идти через 2 подключения — Seven и МСН Телеком.
